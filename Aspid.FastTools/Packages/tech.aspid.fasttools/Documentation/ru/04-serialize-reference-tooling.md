# SerializeReference Tooling

Находите потерянные `SerializeReference` в префабах, ассетах и сценах, восстанавливайте их группами и проверяйте проект перед сборкой. Окно FastTools показывает сохранённые ссылки, в том числе те, которые обычный инспектор уже не отображает.

## Проверить проект

1. Сохраните изменённые сцены и ассеты: проектный поиск читает файлы на диске.
2. Откройте **Tools → Aspid 🐍 → FastTools → Project References**.
3. Нажмите **Scan Project**. Результаты сгруппируются по сохранённому типу.
4. Выберите группу и нажмите **Fix all**, чтобы назначить замену, или используйте предложенный **Smart Fix**.
5. Повторите сканирование и проверьте результат в затронутых ассетах.

Если нужно восстановить одно видимое поле, используйте [Fix в инспекторе](03-serialize-reference-selector.md#восстановление-потерянного-типа).

## Окна аудита и восстановления

| Вкладка | Когда использовать | Что показывает |
|---|---|---|
| **Asset References** | Разобрать один ассет | Граф managed-ссылок по компонентам и путям полей, общие и осиротевшие ссылки, состояния `MISSING` и `SHARED` |
| **Project References** | Проверить весь проект после изменений типов | Группы потерянных типов и ожидающих миграций с действиями `Fix all`, `Smart Fix`, `Migrate all` |

Обе вкладки доступны через **Tools → Aspid 🐍 → FastTools**. **Asset References** строит граф из YAML и позволяет назначить замену прямо на карточке ссылки. **Project References** сканирует `.prefab`, `.asset` и `.unity` под `Assets/`, учитывая исключённые папки.

> [!NOTE]
> Для анализа нужны текстовые YAML-ассеты. Используйте **Asset Serialization → Mode → Force Text** в настройках редактора Unity; уже существующие двоичные ассеты потребуется пересохранить.

### Миграции с MovedFrom

Если старое имя однозначно сопоставляется с совместимым типом через `[MovedFrom]`, группа отображается как ожидающая миграция. **Migrate all** записывает новое имя в файлы. Удалять атрибут можно после миграции всех данных, которые должны продолжать загружаться, включая данные вне текущего проекта.

Ожидающая миграция не считается потерянным типом для проверки сборки. **Smart Fix** лишь предлагает замену; он не применяет её автоматически.

## Проверка перед сборкой

Откройте **Project Settings → Aspid FastTools → SerializeReference** и выберите режим **Build / CI gate**:

| Режим | Сборка плеера | CI-запуск |
|---|---|---|
| `Off` | Проверка пропускается | Проверка пропускается, код `0` |
| `Warn` | Предупреждение, сборка продолжается | Нарушения записываются в журнал, код `0` |
| `Fail` | Потерянные ссылки прерывают сборку | При нарушениях код `1` |

**Сборка плеера проверяет потерянные типы.** Пустые поля с `[TypeSelector(Required = true)]` дополнительно проверяются при отдельном CI-запуске с `-srGateRequired`.

### Общие и личные настройки

| Настройка | Где хранится | Назначение |
|---|---|---|
| **Build / CI gate** | В проекте | Строгость проверки |
| **Excluded scan folders** | В проекте | Папки, пропускаемые проектными сканированиями |
| **Auto de-alias duplicated list elements** | В проекте | Независимая копия при дублировании элемента списка |
| **Breakage detection** | Локально, `EditorPrefs` | Уведомление и предупреждение в Console о новых потерянных ссылках после импорта или перекомпиляции |

Общие настройки сохраняются в `ProjectSettings/SerializeReferenceSharedSettings.asset`. Добавьте файл в систему контроля версий, чтобы команда и CI использовали одинаковые правила.

<details>
<summary>Другие настройки окна и селектора</summary>

Те же параметры доступны во вкладке **Settings** окна FastTools и в **Preferences → Aspid FastTools**. Рядом находятся личные настройки:

- **Favorites** — отображение избранного.
- **Recent items** — ёмкость истории от 0 до 20. Значение 0 скрывает секцию и приостанавливает запись, сохраняя историю.
- **Saved lists** — очистка Favorites и Recent.
- **Welcome** — автоматический показ приветствия.

Зелёная полоска обозначает настройки проекта, синяя — личные. **Reset to defaults** сбрасывает каждую группу отдельно и сохраняет списки Favorites и Recent. Изменения сразу отражаются во всех представлениях настроек.

Цвет общей ссылки определяется её идентификатором: одинаковый цвет помогает найти поля, использующие один экземпляр. Отдельной настройки цвета нет.

## Запуск в CI

Запустите Unity в batchmode из корня Unity-проекта. Здесь `Unity` обозначает исполняемый файл установленного редактора; если его нет в `PATH`, укажите полный путь.

```bash
Unity -batchmode -quit -projectPath . \
  -executeMethod Aspid.FastTools.SerializeReferences.Editors.SerializeReferenceCiGate.RunCheck \
  -srGateReport SerializeReferenceGateReport.txt \
  -srGateRequired -srGateFail
```

Команда проверяет потерянные типы и незаполненные обязательные поля, создаёт отчёт и завершает процесс с кодом `1` при нарушениях. `-srGateFail` явно включает строгий режим, даже если в настройках проекта выбран `Off`.

| Флаг | Действие |
|---|---|
| `-srGateReport <path>` | Путь отчёта. По умолчанию — `SerializeReferenceGateReport.txt` в корне проекта |
| `-srGateRequired` | Дополнительно проверять незаполненные поля с `Required = true` |
| `-srGateFail` | Использовать `Fail` вместо режима проекта |
| `-srGateWarnOnly` | Использовать `Warn`; имеет приоритет над `-srGateFail`, если переданы оба |

Без флага строгости используется настройка проекта. В режиме `Off` сканирование и запись отчёта пропускаются. В режиме `Warn` нарушения выводятся в журнал, но процесс возвращает `0`; для CI ориентируйтесь на код выхода.

### Границы проверки Required

В префабах и ScriptableObject проверка идёт через сериализованные свойства. Сцены читаются из YAML: проверяются поля верхнего уровня и поля внутри сериализуемых по значению контейнеров. Проход по сценам не спускается в элементы коллекций и внутрь managed-ссылок.

### Отчёт и коды выхода

После строк заголовка каждая строка нарушения содержит значения, разделённые табуляцией:

```text
KIND    assetPath    fileId    rid    StoredType    fieldPath
```

`fieldPath` может быть пустым для потерянного типа. Сохраните отчёт как артефакт CI, чтобы по пути ассета и идентификатору ссылки найти проблему.

| Код | Значение |
|---|---|
| `0` | Нарушений нет, выбран `Warn` или проверка отключена |
| `1` | Обнаружены нарушения в режиме `Fail` |
| `2` | Внутренняя ошибка проверки, например не удалось записать отчёт |
