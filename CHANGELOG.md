## [Unreleased]

First stable release. The earlier `1.0.0-rc.*` prereleases are on [GitHub Releases](https://github.com/VPDPersonal/Aspid.FastTools/releases); the notes below list what changed since `1.0.0-rc.8`.

### Added

- Type dropdowns show the type's icon left of its name: the `[TypeSelectorDisplay]` icon, else Unity's icon for the type. **Type icons** under Appearance in the Settings tab turns them off.
- **Field stripes** under Appearance in the Settings tab hides the status stripe left of `[SerializeReference]`, `[TypeSelector]`, `SerializableType` and `SerializableMonoScript` fields in the Inspector, and the gutter a shared reference leaves for it. The notices under the fields stay.
- In the Settings tab the Right arrow turns a focused switch on and the Left arrow turns it off; Enter still flips it.
- Alt+Shift+R (Option+Shift+R on macOS) opens Asset References on the selected asset from any Editor window. Rebind it as Aspid FastTools/Open Asset References in the Shortcuts window.
- The FastTools window switches tabs with Alt+Left and Alt+Right (Option on macOS), next to Ctrl+Tab. Rebind them under Aspid FastTools/Window in the Shortcuts window.
- `RemoveChildren` and `RemoveChildrenIf` remove several children in one call and take the same `params`, `IEnumerable`, `List` and `ReadOnlySpan` overloads as `AddChildren`.
- `AddClasses`, `RemoveClasses`, `ToggleClasses` and `EnableClasses` change several USS classes in one call and take the same `params`, `IEnumerable`, `List` and `ReadOnlySpan` overloads as `AddChildren`. An `IEnumerable` may read `GetClasses()` of the same element. `EnableClasses` takes the flag first: `EnableClasses(isFree, "selected", "free")`.
- `AddAspidTheme()` gives an element of your own editor window the colours of the FastTools windows: the palette of the editor skin and the theme picked under **Appearance**, a theme of the project included. The element follows a new pick at once, and the style sheets you add after it read the `--aspid-colors-*` tokens.
- `TypeSelectorWindow.Show` takes a style sheet. The picker then takes the FastTools palette and theme, light on the light skin, in place of the colours of Unity's popups, and the sheet comes on top, so the picker can match the window that opens it.
- `InsertStyleSheet` inserts a style sheet at an index, `EnableStyleSheet(sheet, enable)` adds or removes it, and `ClearStyleSheets` removes every style sheet.
- `AddStyleSheets`, `InsertStyleSheets`, `RemoveStyleSheets` and `EnableStyleSheets` take several style sheets, with the same overloads as `AddClasses`.
- Every style sheet method has a `…FromResources` variant; the plural ones take several paths: `AddStyleSheetsFromResources("UI/Base", "UI/Dark")`.
- Every class and style sheet method has an `…If` variant, for example `AddClassIf`, `EnableClassIf` and `AddStyleSheetFromResourcesIf`.
- `ToggleButtonGroup` gets typed `SetValue`, `AddValueChanged`, `RemoveValueChanged` and `SetLabel` overloads for `ToggleButtonGroupState`, so calls such as `AddValueChanged(evt => …)` need no type arguments.
- `GUIDField` (Unity 6000.4+) gets the same chainable setters as `Hash128Field`: `SetLabel`, `SetReadOnly`, `SetMaxLength` and the other text-input and text-selection setters, so `SetLabel("Id")` needs no type arguments.
- `RectIntField` gets a typed `SetLabel`, so `SetLabel("Area")` needs no type arguments, as on `RectField`.
- `DropdownField`, `PopupField<T>`, `RadioButtonGroup` and `MinMaxSlider` get chainable setters: `SetChoices` for the first three, `SetIndex`, `SetFormatListItemCallback` and `SetFormatSelectedValueCallback` for the popup fields, and `SetLowLimit`, `SetHighLimit`, `SetMinValue` and `SetMaxValue` for `MinMaxSlider`. `SetChoices` needs no type arguments; `DropdownField.SetChoices` also takes any `IEnumerable<string>`, such as an array, and copies it. The other setters of `PopupField<T>` need them (`SetIndex<PopupField<int>, int>(1)`); `DropdownField` has overloads without them.
- `SetBackgroundImage` takes a `Sprite` or a `VectorImage` as well as a `StyleBackground`: `icon.SetBackgroundImage(sprite)`.
- From Unity 6000.6, `SetTextSelf` also takes an `int`, a `long`, a `ulong`, a `float` with a format, a `ReadOnlySpan<char>`, a `StringBuilder` or a `char[]` slice and sets the text through Unity's allocation-free `TextElement.SetText`, so text that changes every frame needs no `ToString()`. An element that is not attached to a panel yet gets the string instead, without Unity's warning.
- `SetRootItemsSelf` fills a `TreeView` or `MultiColumnTreeView` in a chain: `tree.SetAutoExpand(true).SetRootItemsSelf(items)`.
- `ScrollView`, `TabView`, `Tab` and `TwoPaneSplitView` get chainable setters. `ScrollView`: `SetMode`, `SetHorizontalScrollerVisibility`, `SetVerticalScrollerVisibility`, `SetScrollOffset`, `SetHorizontalPageSize`, `SetVerticalPageSize`, `SetMouseWheelScrollSize`, `SetScrollDecelerationRate`, `SetElasticity`, `SetElasticAnimationIntervalMs`, `SetTouchScrollBehavior`, `SetNestedInteractionKind`. `TabView`: `SetActiveTab`, `SetSelectedTabIndex`, `SetReorderable`, `AddActiveTabChanged`, `AddTabReordered`, `AddTabClosed` and their `Remove…` pairs. `Tab`: `SetLabel`, `SetIconImage`, `SetCloseable`, `AddSelected`, `AddClosing`, `AddClosed` and their `Remove…` pairs. `TwoPaneSplitView`: `SetFixedPaneIndex`, `SetFixedPaneInitialDimension`, `SetOrientation`.
- `ListView`, `TreeView` and the other collection views get `SetShowBorder`.
- `RegisterCallbackSelf`, `RegisterCallbackOnceSelf` (the callback runs for one event) and `UnregisterCallbackSelf` add and remove an event callback in a chain, with the `userArgs` and `TrickleDown` parameters of Unity's `RegisterCallback`: `button.RegisterCallbackSelf((PointerEnterEvent evt) => Hover()).SetTooltip("Apply")`.
- `TextField`, `IntegerField`, `LongField`, `UnsignedIntegerField`, `UnsignedLongField`, `FloatField`, `DoubleField` and `Hash128Field` get chainable setters: `SetMaxLength`, `SetMaskChar`, `SetDelayed`, `SetReadOnly`, `SetPassword`, `SetPlaceholder`, `SetHidePlaceholderOnFocus`, `SetKeyboardType`, `SetAutoCorrection`, `SetHideMobileInput`, `SetHideSoftKeyboard`, and for text selection `SetSelectable`, `SetSelectAllOnFocus`, `SetSelectAllOnMouseUp`, `SetDoubleClickSelectsWord`, `SetTripleClickSelectsLine`, `SetCursorIndex`, `SetSelectIndex`, `AddOnCursorIndexChange` / `RemoveOnCursorIndexChange`, `AddOnSelectIndexChange` / `RemoveOnSelectIndexChange`. The `ITextEdition` and `ITextSelection` setters do not reach these fields. Other value types use `TextInputBaseFieldExtensions` and `TextInputBaseFieldTextSelectionExtensions`.
- `TextField` gets `SetMultiline` and `SetVerticalScrollerVisibilitySelf`; the name has `Self` because Unity's own obsolete `SetVerticalScrollerVisibility` hides an extension of that name. `IntegerField`, `LongField`, `UnsignedIntegerField`, `UnsignedLongField`, `FloatField` and `DoubleField` get `SetFormatString`; other `TextValueField<T>` types use `SetFormatString<TField, TValue>` of `TextInputBaseFieldExtensions`.
- Added `AndApplyWithoutUndo` counterparts for every `SerializedProperty` setter with immediate application, including `SetValue` overloads, object references, enums, and array size helpers.
- `SetEnum`, `SetEnumAndApply` and `SetEnumAndApplyWithoutUndo` write an enum value to a `SerializedProperty`, and `SetValue(Rarity.Rare)` calls them. `SetEnumIndex` takes an index into the enum entries, not a value: for `Rare = 20` the call `SetEnumIndex((int)Rarity.Rare)` picks the wrong entry.
- On Unity 6000.4 and later, `SetGuid`, `SetGuidAndApply`, `SetGuidAndApplyWithoutUndo` and the `SetValue` overloads write a `GUID` field; it needed `SetBoxed` before.
- **Settings** and **Preferences → Aspid.FastTools** get an **Appearance** section. Its **Theme** dropdown recolors the FastTools windows and the type picker: **Default** (near-black cards, green accent), **Venom** (the blue-black palette of the documentation site with its blue accent) or **Unity** (the greys of Unity's editor skin, so the windows read as editor panels), each with a light variant for the light editor skin. The success status stays green in all of them. The accent of links, focus and hover borders, the active tab, buttons, switches, and the Welcome title and logo moved into its own `--aspid-colors-accent-*` and `--aspid-icons-accent` tokens, so a theme can change it apart from the success status; `--aspid-colors-surface-control` and `--aspid-colors-surface-field` set the fills of the buttons and drop-downs, and of the value boxes, in the settings; `--aspid-radius-card` and `--aspid-radius-control` set their corners, `--aspid-colors-slider-track` the slider track, `--aspid-colors-dots-1` to `-3` colour the dots behind the windows, and `--aspid-dots-radius: 0` hides them. Below the built-in themes the dropdown lists the themes of the project, the `.uss` sheets in `Assets` with the `AspidFastToolsTheme` label, and **Create theme…** at its end copies the current theme into a new sheet, labels it and picks it. A theme of the project is picked for that project, a built-in one for every project on the machine. Picking a theme recolors the windows that are already open, and a sheet picked earlier as the theme override becomes the theme of the project. In the Settings tab, Enter opens the dropdown and the Left and Right arrows step through the themes.
- **Tools → Aspid 🐍 → FastTools → Sample Themes** opens a window that previews the EnumValues, Types, SerializeReferences and ProfilerMarkers sample scenes in **Light** or **Dark** colours. The preview works in Edit Mode and Play Mode; **Authored**, the default, keeps the scene's own colours. The window edits the shared palettes and saves them in `ProjectSettings/AspidFastToolsSampleThemes.asset`. It hooks the editor update loop, camera rendering and scene saving only while **Light** or **Dark** is on.
- Analyzer `AFT0009` (warning) — two `[TypeSelector]` base types have no type in common, so the selector is empty.
- Analyzer `AFT0012` (warning) — `[TypeSelector]` on a field Unity does not serialize, so the Inspector never shows it: a non-public field without `[SerializeField]` or `[SerializeReference]`, an auto-property without `[field: SerializeField]`, or a `static`, `const`, `readonly` or `[NonSerialized]` field.
- Analyzer `AFT0010` (warning) — a `this.Marker()` call opens no profiler marker because the generator cannot support it: it is written in a `private` or `protected` type (or a type nested in one), in an interface (a default interface method) or in a type that reuses a type parameter name of a containing type; its receiver is of another type (`other.Marker()`, calls in static classes); it has an explicit argument (`this.Marker(5)`) or a type argument; or it is `this?.Marker()`, the static call form, a method group or a call inside an expression tree. The generator emits no marker for such calls.
- Analyzer `AFT0011` (warning) — the scope of `this.Marker()` is discarded (`this.Marker();` as a statement, `_ = this.Marker();`, a local nothing reads), so the sample it begins never ends.
- `SerializeReferenceIMGUIList.Draw(listProperty, label, baseTypes)` takes the element type from the list field, like `SerializeReferenceEditorGUI.CreateList`; the overload with `elementType` stays.
- `EnumValues<TEnum, TValue>` and `EnumValues<TValue>` get `TryGetValue`, which tells a matching row from the **Default Value** fallback, and `Count`, the number of rows that `foreach` yields. `EnumValues<TValue>` also gets `GetValue<TEnum>` and `TryGetValue<TEnum>`, which take the key without boxing it; a call such as `table.GetValue(damageType)` binds to them after a recompile.
- Analyzer `AFT0013` (warning) — a `this.Marker()` scope stays open across `yield return` or `await`: the coroutine or `async` method resumes in a later frame or on another thread, so the Profiler gets unbalanced samples.
- Analyzer `AFT0014` (warning) — a `WithName` name the generator cannot read at compile time, such as a variable, so the marker keeps the member name.
- Every analyzer diagnostic has a description of the fix and a help link to its documentation page; Rider and Visual Studio used to open a web search for the ID.
- Missing `[SerializeReference]` types set by prefab instance overrides (prefab variants, nested prefabs, prefab instances in scenes) are now found: the build / CI gate counts them as missing types, Project References lists them in a **Prefab instance overrides** card, and the delete guard and breakage detection count them. They are not rewritten; fix them on the instance or revert the override. An old name that `[MovedFrom]` maps is listed there as a pending migration, since **Migrate all** does not rewrite overrides. The CI report gains a trailing `origin` column, `override` for these rows.
- **Assets → Aspid 🐍 → FastTools → Asset References**, in the main menu and the right-click menu of the Project window, opens Asset References on the selected prefab, ScriptableObject, scene or prefab instance; the item is disabled for any other selection.
- `-srGateStrict` makes the CI check count the files it could not check (unfetched Git LFS files, binary assets that can hold references) as violations, so under `Fail` a run without `git lfs pull` no longer passes with exit code `0`.
- The CI report gains trailing `ns` and `asm` columns with the stored namespace and assembly of a `MissingType` row. The build and CI logs name a missing type with its namespace (`Game.Pistol`, not `Pistol`), so same-named classes can be told apart.
- A `[SerializeReference]` field whose class or own data is overridden on a prefab instance has a bold label, and its header menu offers **Revert** and **Apply to Prefab 'Name'**, as Unity's own fields do. A change inside a nested reference marks only the changed field, and **Apply** is not offered on a prefab variant selected in **Project**. The blue override bar is not drawn, and a selection of several objects shows neither.
- A `SerializableType` or `SerializableMonoScript` field or a `[TypeSelector]` string whose stored type no longer resolves shows a **Missing type** notice under the field. **Fix** opens the type picker to choose a replacement. When the class only moved to another namespace or assembly and exactly one compatible type has its name, a **→ TypeName** button replaces the stored name in one click. The caption shows the type name without its assembly, `<Missing Game.Combat.Spear>`, and the tooltip shows the whole stored name.
- `TypeField.AssemblyQualifiedName` returns the stored name of a missing type, for which `value` is `null`, so a custom editor can save the name back unchanged. `TypeField.ExcludeEditorOnlyTypes` is now public: an unbound field can leave out types from editor-only assemblies, as a bound field on a runtime object does.
- `SerializableType`, `SerializableMonoScript` and their generic variants get `IsEmpty` (no type is stored) and `IsMissing` (a name is stored but no longer resolves); `Type` is `null` in both cases. Unity fills a serialized field with an empty wrapper when it loads an asset, a scene or a prefab, so `field == null` alone misses an unset one: test `field is null || field.IsEmpty`.
- Missing `SerializableType` and `SerializableMonoScript` names are found across the project. **Project References → Scan Project** lists them in **type name** groups with **Fix all**, **Smart Fix** and **Undo**; prefab instance overrides and fields in managed references are rewritten too. The build / CI gate reports them as `MissingTypeName` rows, with the stored name in the `className` column and the wrapper field in `fieldPath`, and breakage detection reports a name that stops resolving. `[TypeSelector]` strings are still checked only in the Inspector.

### Changed

- The IMGUI drawer of `EnumValues` looks like the UI Toolkit one: the field name sits above the type field, which spans the full width, a line separates the header, **Default Value** is no longer indented, and the **Values** header is plain text instead of bold on a band.
- **Excluded scan folders** in the Settings tab reads as one of Unity's lists: its caption and the folders share one framed block, each folder has a **−** at the end of its row, and the last row (or the **List is empty** row) has the **+**. A click selects a folder and a double click picks another one for it. With the keyboard, Enter or Delete on a focused folder removes it, and its **−** lights up while it has the focus.
- The minimum Unity version is now 6000.0.53f1 instead of 6000.0.0f1. The package uses UI Toolkit APIs that later 6000.0 patches added (`IStyle.unityEditorTextRenderingMode`, `IStyle.unitySliceType`, `UxmlElement.libraryPath`), so it did not compile on earlier patches.
- The package no longer ships the `Documentation` folder with its pages and images, so they are not imported into your project; the documentation lives on the site: https://vpdpersonal.github.io/Aspid.FastTools/. The samples ship no README either: a sample description in the Package Manager ends with a link to its tutorial on the site, and the sample card on the Welcome tab shows it as a **Tutorial** link.
- The package `README.md` no longer gives the git URL, so an Asset Store buyer does not add a second copy of the package; the git URL install stays on the site.
- The Agent Skills for this package moved from the `aspid-fasttools` Claude Code plugin in [Aspid.Claude.Plugins](https://github.com/VPDPersonal/Aspid.Claude.Plugins) into this repository (`skills/`). Install them into Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI or another agent with `npx skills add VPDPersonal/Aspid.FastTools#skills`, or `#skills-preview` for a preview version: `npx skills update` then follows the releases of that channel, never `main`; the plugin is no longer published. A plugin you installed stays on your machine and teaches the agent API that no longer exists: remove it in Claude Code with `/plugin uninstall aspid-fasttools@aspid-claude-plugins`.
- The samples have a new look. Every sample ships a `Fonts` folder with IBM Plex Serif, IBM Plex Mono and iA Writer Quattro S under the SIL Open Font License 1.1 (the license texts lie next to the fonts). The scene samples (EnumValues, Types, SerializeReferences, ProfilerMarkers) also ship a `Materials` folder with colour materials and a `Shaders` folder with a small `Studio` shader. The Ability Catalog of the EditorTools sample uses the fonts through `SampleFonts.uss` and takes the FastTools theme through `AddAspidTheme()`; its **Effect** field opens the type picker in place of the **Change…** button and shows the `[TypeSelectorDisplay]` name and icon of the effect, **+** replaces **Create**, **Reset to defaults** replaces **Halve cooldown, +5 MP**, and the buttons of a row select its asset or move it to the trash. The samples grow from about 0.2 MB to about 3 MB, most of it font copies: a sample is imported on its own, so each one carries its own.
- Renamed `GetScriptName()` to `GetDisplayName()` and `GetScriptNameWithIndex()` to `GetDisplayNameWithIndex()`; update existing calls to the new names. Both methods now return `string.Empty` for null or destroyed objects. Component indexing uses a pooled list instead of temporary arrays and LINQ.
- Renamed VisualElement extensions; update existing calls:
  - `SetIsDelayed` / `SetIsPassword` / `SetIsReadOnly` / `SetIsSelectable` → `SetDelayed` / `SetPassword` / `SetReadOnly` / `SetSelectable`;
  - `IsFocus` → `IsFocused`, `SetFocus` / `SetBlur` → `FocusSelf` / `BlurSelf`;
  - `EnableInClass` / `ToggleInClass` → `EnableClass` / `ToggleClass`;
  - `AddStyleSheetsFromResource` / `RemoveStyleSheetsFromResource` → `AddStyleSheetFromResources` / `RemoveStyleSheetFromResources`; `AddStyleSheets(sheet)` and `RemoveStyleSheets(sheet)` still compile, as the plural names now take several style sheets;
  - `SetImageFromResource`, `SetSpriteFromResource`, `SetVectorImageFromResource`, `SetBackgroundImageFromResource` → `…FromResources`;
  - `MarkDirtyLayout` → `MarkDirtyLayoutSelf`: `IMGUIContainer.MarkDirtyLayout()` hid the old extension, so the call returned `void`; the new name chains.
  - `SetText` of `TextElement` (`Label`, `Button` and others) → `SetTextSelf`: from Unity 6000.6 a string argument binds to Unity's own `TextElement.SetText(ReadOnlySpan<char>)`, which returns `void`, so chains such as `label.SetText(x).SetTooltip(y)` failed to compile; the new name chains on every Unity version. `SetText` of `Foldout`, `HelpBox` and `Toggle` keeps its name.
- A bare `null` argument to `SetBackgroundImage` and, from Unity 6000.6, to `SetTextSelf` no longer compiles, because the new overloads fit it as well. Cast it, for example `(string)null`, or pass `StyleKeyword.None` to clear a background.
- Renamed the extension classes `BaseFieldExtensionsSetLabel<Type>` to `BaseField<Type>Extensions` (`BaseFieldExtensionsSetLabelInt` → `BaseFieldIntExtensions`) and `ProgressBarExtensions` to `AbstractProgressBarExtensions`. Extension-method calls are unaffected; only calls through the class name change.
- Renamed the extension class `SerializePropertyExtensions` to `SerializedPropertyExtensions`. Extension-method calls are unaffected; only calls through the class name change, such as `SerializePropertyExtensions.GetFieldInfo(property)`.
- `SetShowMixedValue` no longer defaults its argument to `true`; pass the value explicitly.
- `SetDirection`, `SetFill`, `SetInverted`, `SetPageSize` and `SetShowInputField` now return the slider's own type (`Slider`, `SliderInt`) instead of `BaseSlider<TValue>`, so a chain keeps the slider's members. They accept `BaseSlider<float>` and `BaseSlider<int>`; the open `BaseSlider<TValue>` overloads are gone. The `BaseSlider<int>` overloads live in the new `SliderIntExtensions` class: extension-method calls are unaffected, but a call through `SliderExtensions.` on a `SliderInt` must switch to `SliderIntExtensions.`.
- The parameterless constructors of `SerializableType` / `SerializableType<T>` are no longer public: create a wrapper with `new SerializableType(type)` or `new SerializableType<T>(type)` (`null` gives an empty one). `SerializableMonoScript` / `SerializableMonoScript<T>` have no public constructors: declare them as serialized fields and pick the script in the Inspector.
- `SerializableType`, `SerializableMonoScript` and their generic variants now compare by value; `Equals` and `GetHashCode` used to compare references. Wrappers that store the same type name are equal and share a hash code, so they work as `Dictionary` and `HashSet` keys, and `List.Contains` and `IndexOf` find an equal wrapper. `==` still compares references.
- `[TypeSelector]` on a `[SerializeReference]` field now offers only types assignable to every attribute type — the rule `string` and `SerializableType` fields already follow; it used to offer types matching any one of them. The same applies to `baseTypes` of `SerializeReferenceEditorGUI.CreateField`, `CreateList` and `DrawFieldLayout`. A list of alternatives such as `typeof(Pistol), typeof(Rifle)` now leaves the selector empty and triggers `AFT0009`: give the allowed classes a common interface or base class and pass that instead. `AFT0005` now checks all attribute types together.
- The `[TypeSelector]` analyzer no longer resolves the attributes of fields without `[TypeSelector]` and skips assemblies that do not reference the package; it used to slow down every compilation of a large project.
- An IMGUI inspector no longer runs a full duplicate scan of a `[SerializeReference]` list for every element on every GUI event, only once per list per editor update or when the list size changes; a shared field no longer creates a `SerializedObject` on every repaint.
- Breakage detection keeps its baseline in memory and writes it to the session once, before a script reload, instead of parsing and rewriting all of it on every asset save, which cost milliseconds per thousand assets. Its start-up read decodes only the assets that hold a managed reference or a type name, instead of reading every asset in full.
- Deleting or moving an asset no longer drops the warm usage index of Project References, the delete guard and breakage detection. A delete removes the usages of that asset, a move into or out of an **Excluded scan folder** removes or adds them, and a move between scanned folders changes nothing. An import of more than 64 scanned assets drops the index once instead of patching it asset by asset.
- `GetFieldInfo()` and `GetDeclaringInstance()` cache the field lookup, and the check that decides whether a nested `[SerializeReference]` field has its own drawer is cached per field. An IMGUI inspector no longer creates arrays or attribute instances for every nested reference on every event, and creates fewer strings, so a large tree allocates less while the mouse moves.
- **Fix all**, **Smart Fix**, **Migrate all**, `<None>` and the summary's **Undo** in Project References no longer read a file again for every broken reference in it, and write it once. They check only once per file whether it is open or has unsaved changes, so a file with many broken references is repaired much faster.
- An empty `[SerializeReference]` field no longer parses the asset file on every repaint to check for a missing type: an unchanged file is read once, so empty fields in a large scene or prefab no longer slow the Inspector down.
- In the Inspector of a runtime object, the type picker no longer offers types from editor-only assemblies (`UnityEditor`, Editor asmdefs and `Editor` folders): a player cannot resolve them, so the value silently became `null` or a missing reference in a build. Fields of editor windows and other editor-only objects still offer every type.
- **Paste**, **Paste Template**, *Link to Existing*, a dropped script and **Smart Fix** follow the same rule in the Inspector of a runtime object: they no longer assign a type from an editor-only assembly or a generic type closed over one. The type picker of Asset References no longer offers such types for a runtime object either. **Create New Script…** leaves the field as it is and logs a warning when the new script is saved in an `Editor` folder.
- The unconstrained type picker (`SerializableType` without `T`, `[TypeSelector]` on a string, `TypeField`) reuses its type list between openings instead of rebuilding it from every loaded type each time.
- The type picker checks the field's base type first when it lists the loaded types, so a picker with a narrow base type, such as the **+** of a `[SerializeReference]` list of a specific interface, opens several times faster in a large project. An IMGUI type field resolves a stored type name once instead of on every repaint, which a missing type made slow.
- A type picker with a predicate, such as the picker of a `SerializableMonoScript` field, `TypeField.Predicate` or a `[SerializeReference]` field, no longer checks every loaded type again each time it opens: the types that pass everything but the predicate are listed once per set of base types and reused until an assembly loads, and only the predicate runs on each opening. In a project with about 55,000 loaded types, the picker of a `SerializableMonoScript` field opens in about 6 ms instead of about 85 ms, and the picker of a `[SerializeReference] object` field in about 90 ms instead of about 190 ms.
- `TypeField(string label, Type defaultValue = null)` is split into `TypeField(string label)` and `TypeField(string label, Type defaultValue)`, and `InspectorTypeField` likewise. `new TypeField(null)` used to pick the property constructor and throw `NullReferenceException`; it no longer compiles, so name the argument: `new TypeField(label: null)`. The bound constructors throw `ArgumentNullException` for a `null` property and `ArgumentException` for a property that is not a string. With `binding-path` set in UXML, the field logs a warning that it can be bound only from C#.
- Reading `Type` of `SerializableType` and `SerializableMonoScript` opens a Profiler marker only for the lookup of the type, not for a cached read, so reading it for many objects every frame no longer fills the Profiler with samples.
- `EnumValues` opens a Profiler marker only when it builds its entries on first access, not in `GetValue`, `TryGetValue` and `Equals`, so a lookup for many objects every frame no longer fills the Profiler with samples.
- `SerializeReferenceIMGUIList.Draw` now throws `ArgumentNullException` for a `null` property and `ArgumentException` for a property that is not a list of managed references, like `SerializeReferenceEditorGUI.CreateList`; it used to draw nothing. A `null` label now shows the property's display name; pass `GUIContent.none` to hide it.
- Renamed the `currentAqn` parameter of `TypeSelectorWindow.Show` to `assemblyQualifiedName`, like the other parameters that take an assembly-qualified name. Update calls that pass it by name: `currentAqn: name` becomes `assemblyQualifiedName: name`. Positional calls need no change.
- The generated `this.Marker()` code now declares its marker fields only under `ENABLE_PROFILER`, like the `Marker()` body that reads them: builds without the profiler no longer create every marker in a static constructor.
- `ProfilerMarkerExtensionsForGenerator.Marker(this object)` is now `Marker<T>(this T, [CallerLineNumber] int line = -1)`: a struct call site the generator cannot mark is no longer boxed, so a Burst job still compiles. It takes the same parameters as the generated overload, so a type without a namespace, as in Unity's script template, gets its markers too. A `this.Marker()` call inside an expression tree no longer compiles (CS0854), and a method group now needs `Func<int, AutoScope>`.
- A generic class names nested type arguments the way C# writes them (`Foo<List<Int32>>.Run (line)`, `Foo<Outer<Int32>.Inner>.Run (line)` instead of ``Foo<List`1>``, `Foo<Inner>`). A generic struct gets one marker per call site for all its closed types, named `Job<T>.Execute (line)`, because Burst cannot run the per-type label.
- The generated `Marker()` dispatches on the line with a `switch`, so its cost no longer grows with the number of call sites in a type.

- `Persistent()` keeps the `context` of the source `SerializedObject`, so an `ExposedReference` read or written through the copy resolves in the same table (for example a `PlayableDirector`) instead of the default value in the asset.
- *Link to Existing* in the `[SerializeReference]` context menu now offers only instances the field's type picker accepts under its `[TypeSelector]` base types, including member-referenced ones; it used to offer any instance assignable to the declared field type.
- A generic class picked in the `[SerializeReference]` type picker now fits every `[TypeSelector]` type: a closed type outside the attribute, such as `Modifier<Int32>` under `[TypeSelector(typeof(IModifier<float>))]`, shows an error. It used to be stored although the attribute rejects it.
- The type picker infers generic arguments from every `[TypeSelector]` type: when they pin every argument, as `[TypeSelector(typeof(IModifier<float>))]` pins `Modifier<T>` to `Modifier<Single>`, picking the generic closes it at once. It used to look only at the field type of a `[SerializeReference]` field, and at the first `[TypeSelector]` type elsewhere.
- On a generic argument page of the `[SerializeReference]` type picker, a nested generic is checked like any other argument: a class without `[Serializable]` and a .NET generic struct such as `Nullable<T>` or `KeyValuePair<,>`, whose values Unity silently drops, are no longer offered. Your own `[Serializable]` generic struct can now be a nested argument, as in `Container<Optional<int>>`.
- The `[SerializeReference]` type picker no longer offers or accepts, as a generic argument, a .NET type that carries `[Serializable]` but whose values Unity silently drops: `DateTime`, `TimeSpan`, `Guid`, `Decimal`, `Dictionary<,>`, `HashSet<T>`, `Queue<T>`, `Stack<T>`, `LinkedList<T>`, `Tuple<…>`, `object` and `IntPtr`. Among the .NET types Unity serializes only primitives, `string`, enums, `T[]` and `List<T>`, so those still fit; a multidimensional or jagged array, a `List<List<T>>` and a collection of an element Unity drops are rejected as well. Your own `[Serializable]` types are not affected.
- `SerializeReferenceEditorGUI.CreateField` and `DrawFieldLayout` now add the `[TypeSelector]` constraints of the field to `baseTypes`, as `CreateList` already did. The type picker used to offer every type that fits the declared field type, where `PropertyField` offers only the selected ones. `CreateField` reads the constraint once, when the field is created.
- *Find Usages* in the `[SerializeReference]` context menu now lists usages of the exact type in the field (namespace and assembly included); it used to match every stored class name containing its name, such as `PistolMk2` or a `Pistol` from another namespace. A typed `sr:` query still matches class names by substring.
- *Find Usages of …* and *Link to Existing* in the `[SerializeReference]` context menu name a generic type as the type picker does, `Modifier<Single>` or its `[TypeSelectorDisplay]` name; they used to show ``Modifier`1``. A `/` in a display name no longer opens a submenu.
- In the default UI Toolkit Inspector, **+** of an empty `[TypeSelector]` `[SerializeReference]` list now opens the type picker; it used to append a `<None>` entry, and the picker appeared only once the list had an element.
- The breakage notification and the breakage detection setting point at Project References; they still named its old tab, Repair.

## [1.0.0-rc.8] — 2026-09-06

First release. Unity **6000.0**, assemblies `Aspid.FastTools` / `Aspid.FastTools.Editor`, prebuilt Roslyn DLLs `Aspid.FastTools.Generators` / `Aspid.FastTools.Analyzers`. Every inspector feature works in both IMGUI and UI Toolkit.

### Added

#### Serializable Type System

- `SerializableType` / `SerializableType<T>` — `[Serializable]` wrapper over `System.Type`, lazy resolution, implicit conversion to `Type`, `Type`-taking constructor, `AssemblyQualifiedName`.
- `SerializableMonoScript` / `SerializableMonoScript<T>` — the same, referenced through the script asset so renames and moves do not break it; the player serializes the name alone.
- `SerializableTypeBase` and `ISerializableType` for polymorphic access to any wrapper.
- `[TypeSelector]` — a hierarchical type picker on `string`, `SerializableType` / `SerializableMonoScript` and `[SerializeReference]` fields, and on arrays / lists of them. Base-type constraints, `Allow` (`TypeAllow`), `Required`, member references in string arguments (`Type`, `string`, `SerializableType`, arrays of these, resolved live).
- `[TypeSelectorDisplay]` — `Name`, `Group`, `Tooltip`, `Icon`, `Hidden` for a type's row in the picker.
- `ComponentTypeSelector` — swaps a sibling `Component` in place through a type dropdown.
- `TypeSelectorWindow` with a public `Show(...)` API: namespace tree, search, keyboard navigation, Favorites and Recent, `TypeSelectorFilter` (`Predicate`, `AdditionalTypes`, `HideNoneOption`).
- `TypeField` / `InspectorTypeField` UI Toolkit elements behind the drawers.

#### SerializeReference Selector

- Type dropdown on `[SerializeReference]` fields, nested references included (8 levels deep); custom drawers and `[Header]` / `[Space]` / `[Tooltip]` are honored.
- Open generic implementations: arguments inferred from the field's type arguments and interfaces, otherwise collected on a second picker page.
- Data carry-over on type switch, Copy / Paste, multi-object editing, duplicate de-aliasing.
- Shared-reference notices with **Make unique**, color-coded groups and member navigation.
- Drag a `MonoScript` to assign, named templates, **Link to Existing**, picker-backed list `+`, **Create New Script…**, **Find Usages**.

#### Missing-reference repair

- Inline **Fix** on a missing type, keeping the stored data; works for saved assets, Prefab Mode and scene objects.
- **Smart Fix** ranks the likely replacement (`[MovedFrom]`, same name elsewhere, casing, field-shape match).
- `[MovedFrom]` renames are shown as pending migrations with one-click **Migrate all**, never as violations.
- Breakage notification after a script rename / delete or reimport; delete guard for scripts used as managed references; YAML diff preview before every bulk rewrite.
