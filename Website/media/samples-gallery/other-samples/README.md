# Sample recordings, dark and light

> These recipes need the Sample Themes window, which is removed: `prepare.cs.txt` fails until the media rewrite for the new samples replaces them.

Real Unity 6000.4 camera recordings with the shared Dark and Light previews: the Light one uses a neutral gray platform/background, mint and pale blue accents, subdued grid and lifted animated colors. Authored gameplay runs normally: Types shows regular/elite waves moving to the center plus the placed Archer (3 seconds), SerializeReferences shows real attacks and changing dummy health (6 seconds), ProfilerMarkers shows the flock simulation (6 seconds, deterministic seed 42).

Camera sources are lossless FFV1, 1440 × 810 at 20 fps, one per theme (`<slug>-dark.mkv`, `<slug>-light.mkv`). They are not in this repository: they live in the private [Aspid.Media.Storage](https://github.com/VPDPersonal/Aspid.Media.Storage/tree/main/FastTools/Docs/sample-themes/other-samples) repository under `FastTools/Docs/sample-themes/other-samples/`. Copy them next to `encode.py` before you run it; Git ignores them here. `record.sh <project> <Sample> <Dark|Light>` records one in a hidden batch-mode Editor (asp-unity-capture skill, `editor.sh open`): `prepare.cs.txt` opens the scene in that theme preview, `record.cs.txt` writes the frames in Play Mode. SerializeReferences and ProfilerMarkers replay identically in every run; the Types Archer has a 12-second lifetime, so record both Types themes back to back. The recording helper hides scene title/footer TextMeshes only during each camera render to keep them outside the cropped gameplay illustration, then restores them immediately. The site gallery's scene previews and clips are built by `Website/media/samples-gallery/scenes.py`. Crops, the same for both themes: Types 1204×680 at (100,116), SerializeReferences 888×532 at (276,178), ProfilerMarkers 800×688 at (320,108). No image recoloring or compositing.

The Ability Catalog states in `catalog/<theme>/` are grabs of the real AbilityCatalogWindow at 2x, 1000 × 563 pt (2000 × 1126), from a hidden batch-mode Editor with the pristine EditorTools sample (Arcane Ward, Fireball, Healing Word, Sprint), the Default FastTools theme and the dark or light editor skin; `catalog.cs.txt` has the steps. Fireball starts at 30 MP / 4 s, the real **Reset to defaults** handler sets 10 MP / 1 s and hides the button, and Undo returns 30 / 4 with the button (the undone grab equals `idle.png` byte for byte, so the specs reuse it). `demo.gif` / `demo-light.gif` (2000 × 1126, the whole window, 143 frames) are composed from `idle`, `hover` and `after` with the skill's `compose.py catalog/<theme>/spec.json <frames>` and `encode.sh <frames> <gif>`: one timeline at 25 fps with a composited cursor (idle 0.8 s, move onto the button 0.6 s, hover 0.3 s, after the click 1.0 s, move away 0.4 s, hold 0.6 s, undone 2.0 s). To rerun, follow `catalog.cs.txt` for both skins, then compose and encode both specs. The gallery previews are the idle grab, cropped to 2000 × 1125 and scaled to 1440 × 810.

The ProfilerMarkers page's `profiler-markers.png` / `profiler-markers-light.png` (1102 × 242, the column header and the six Flock rows) are 2x grabs of the real Profiler window, CPU module in Hierarchy view, from a hidden batch-mode Editor in the dark and light editor skins; `profiler-hierarchy.cs.txt` has the step, the column widths and the crop. Both skins show the same recorded frame, so even the timings match.

Run `python3 Website/media/samples-gallery/other-samples/encode.py` from any directory to reproduce the scene GIFs and the Ability Catalog gallery previews. GIFs use 256 colors and sierra2_4a dithering.
