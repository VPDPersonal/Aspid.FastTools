## [Unreleased]

Первый стабильный релиз. Предыдущие prerelease-версии `1.0.0-rc.*` лежат в [GitHub Releases](https://github.com/VPDPersonal/Aspid.FastTools/releases); ниже перечислено, что изменилось с `1.0.0-rc.8`.

### Добавлено

- Добавлены `RemoveChildren` и `RemoveChildrenIf`: удаляют несколько дочерних элементов за один вызов и принимают те же перегрузки `params`, `IEnumerable`, `List` и `ReadOnlySpan`, что и `AddChildren`.
- Добавлены `AddClasses`, `RemoveClasses`, `ToggleClasses` и `EnableClasses`: меняют несколько USS-классов за один вызов, принимают те же перегрузки `params`, `IEnumerable`, `List` и `ReadOnlySpan`, что и `AddChildren`. `IEnumerable` может читать `GetClasses()` того же элемента. `EnableClasses` принимает флаг первым: `EnableClasses(isFree, "selected", "free")`.
- `InsertStyleSheet` вставляет таблицу стилей по индексу, `EnableStyleSheet(sheet, enable)` добавляет или убирает её, а `ClearStyleSheets` удаляет все таблицы стилей.
- `AddStyleSheets`, `InsertStyleSheets`, `RemoveStyleSheets` и `EnableStyleSheets` принимают несколько таблиц стилей с теми же перегрузками, что у `AddClasses`.
- У каждого метода таблиц стилей есть вариант `…FromResources`; методы во множественном числе принимают несколько путей: `AddStyleSheetsFromResources("UI/Base", "UI/Dark")`.
- У каждого метода для классов и таблиц стилей есть вариант `…If`, например `AddClassIf`, `EnableClassIf`, `AddStyleSheetFromResourcesIf`.
- Для `ToggleButtonGroup` добавлены типизированные перегрузки `SetValue`, `AddValueChanged`, `RemoveValueChanged` и `SetLabel` для `ToggleButtonGroupState`, поэтому вызовы вроде `AddValueChanged(evt => …)` не требуют аргументов типа.
- Для `RectIntField` добавлен типизированный `SetLabel`, поэтому `SetLabel("Area")` не требует аргументов типа, как и у `RectField`.
- `SetBackgroundImage` принимает `Sprite` или `VectorImage` наряду со `StyleBackground`: `icon.SetBackgroundImage(sprite)`.
- Начиная с Unity 6000.6, `SetTextSelf` принимает также `int`, `long`, `ulong`, `float` с форматом, `ReadOnlySpan<char>`, `StringBuilder` или срез `char[]` и задаёт текст через `TextElement.SetText` из Unity без выделения памяти, поэтому текст, который меняется каждый кадр, не требует `ToString()`. Элемент, ещё не прикреплённый к панели, получает строку без предупреждения Unity.
- `SetRootItemsSelf` заполняет `TreeView` или `MultiColumnTreeView` в цепочке: `tree.SetAutoExpand(true).SetRootItemsSelf(items)`.
- `RegisterCallbackSelf`, `RegisterCallbackOnceSelf` (обработчик срабатывает на одно событие) и `UnregisterCallbackSelf` добавляют и убирают обработчик события в цепочке, с параметрами `userArgs` и `TrickleDown` как у `RegisterCallback` из Unity: `button.RegisterCallbackSelf((PointerEnterEvent evt) => Hover()).SetTooltip("Apply")`.
- `TextField`, `IntegerField`, `LongField`, `UnsignedIntegerField`, `UnsignedLongField`, `FloatField`, `DoubleField` и `Hash128Field` получили цепочечные сеттеры: `SetMaxLength`, `SetMaskChar`, `SetDelayed`, `SetReadOnly`, `SetPassword`, `SetPlaceholder`, `SetHidePlaceholderOnFocus`, `SetKeyboardType`, `SetAutoCorrection`, `SetHideMobileInput`, `SetHideSoftKeyboard`, а для выделения текста — `SetSelectable`, `SetSelectAllOnFocus`, `SetSelectAllOnMouseUp`, `SetDoubleClickSelectsWord`, `SetTripleClickSelectsLine`, `SetCursorIndex`, `SetSelectIndex`, `AddOnCursorIndexChange` / `RemoveOnCursorIndexChange`, `AddOnSelectIndexChange` / `RemoveOnSelectIndexChange`. Сеттеры `ITextEdition` и `ITextSelection` к этим полям не применяются. Для других типов значений есть `TextInputBaseFieldExtensions` и `TextInputBaseFieldTextSelectionExtensions`.
- Добавлены варианты `AndApplyWithoutUndo` для всех сеттеров `SerializedProperty` с немедленным применением, включая перегрузки `SetValue`, ссылки на объекты, перечисления и методы изменения размера массивов.
- `SetEnum`, `SetEnumAndApply` и `SetEnumAndApplyWithoutUndo` записывают значение перечисления в `SerializedProperty`, а `SetValue(Rarity.Rare)` вызывает их. `SetEnumIndex` принимает индекс записи перечисления, а не значение: для `Rare = 20` вызов `SetEnumIndex((int)Rarity.Rare)` выберет не ту запись.
- На Unity 6000.4 и новее `SetGuid`, `SetGuidAndApply`, `SetGuidAndApplyWithoutUndo` и перегрузки `SetValue` записывают поле `GUID`; раньше для этого нужен был `SetBoxed`.
- В **Settings** и **Preferences → Aspid.FastTools** появился раздел **Appearance**. Поле **Theme override** накладывает `.uss`-файл поверх палитры окон FastTools и окна выбора типа, а **Create template…** создаёт заготовку с токенами в комментариях. Назначение или очистка override перекрашивает уже открытые окна.
- **Tools → Aspid 🐍 → FastTools → Sample Themes** открывает окно, которое показывает сцены примеров EnumValues, Types, SerializeReferences и ProfilerMarkers в цветах **Light** или **Dark**. Предпросмотр работает в Edit Mode и Play Mode; режим по умолчанию **Authored** оставляет собственные цвета сцены. Окно редактирует общие палитры и сохраняет их в `ProjectSettings/AspidFastToolsSampleThemes.asset`. Оно подписывается на цикл обновления редактора, рендер камер и сохранение сцен только при включённом **Light** или **Dark**.
- Анализатор `AFT0009` (предупреждение) — два базовых типа `[TypeSelector]` не имеют общего типа, поэтому селектор пуст.
- Анализатор `AFT0012` (предупреждение) — `[TypeSelector]` на поле, которое Unity не сериализует, поэтому инспектор его не показывает: непубличное поле без `[SerializeField]` или `[SerializeReference]`, автосвойство без `[field: SerializeField]`, а также поле `static`, `const`, `readonly` или `[NonSerialized]`.
- Анализатор `AFT0010` (предупреждение) — вызов `this.Marker()` не открывает маркер профайлера, потому что генератор не может его поддержать: вызов записан в типе `private` или `protected` (или вложенном в такой тип), в интерфейсе (метод интерфейса по умолчанию) либо в типе, который повторяет имя параметра типа внешнего типа; получатель другого типа (`other.Marker()`, вызовы в статических классах); у вызова явный аргумент (`this.Marker(5)`) или аргумент типа; либо это `this?.Marker()`, статическая форма вызова, группа методов или вызов внутри дерева выражений. Для таких вызовов генератор не создаёт маркер.
- Анализатор `AFT0011` (предупреждение) — scope из `this.Marker()` выброшен (`this.Marker();` отдельной инструкцией, `_ = this.Marker();`, локальная переменная, которую никто не читает), поэтому начатый сэмпл никогда не заканчивается.
- У `EnumValues<TEnum, TValue>` и `EnumValues<TValue>` появились `TryGetValue`, который отличает подходящую строку от запасного **Default Value**, и `Count` — число строк, которые отдаёт `foreach`. У `EnumValues<TValue>` также есть `GetValue<TEnum>` и `TryGetValue<TEnum>`: они принимают ключ без упаковки, и вызов вида `table.GetValue(damageType)` после перекомпиляции выбирает их.
- Анализатор `AFT0013` (предупреждение) — scope из `this.Marker()` остаётся открытым через `yield return` или `await`: корутина или `async`-метод продолжают работу в другом кадре или потоке, поэтому Profiler получает несбалансированные сэмплы.
- Анализатор `AFT0014` (предупреждение) — имя в `WithName`, которое генератор не может прочитать при компиляции, например переменная, поэтому маркер сохраняет имя члена.
- У каждой диагностики анализатора есть описание исправления и ссылка на страницу документации; раньше Rider и Visual Studio открывали поиск по ID в интернете.
- Потерянные типы `[SerializeReference]`, заданные override'ами экземпляров префабов (варианты, вложенные префабы, экземпляры префабов в сценах), теперь находятся: build / CI gate считает их потерянными типами, Project References показывает их в карточке **Prefab instance overrides**, а защита от удаления скрипта и детектор поломок их учитывают. Они не переписываются автоматически: исправьте тип на самом экземпляре или отмените override. Старое имя, которое сопоставляет `[MovedFrom]`, показывается там как ожидающая миграция, потому что **Migrate all** не переписывает override'ы. В отчёте CI появился последний столбец `origin`, для таких строк — `override`.
- `-srGateStrict` заставляет CI-проверку считать нарушениями файлы, которые она не смогла проверить (нескачанные файлы Git LFS, двоичные ассеты, способные хранить ссылки), поэтому в режиме `Fail` запуск без `git lfs pull` больше не завершается с кодом `0`.
- В CI-отчёте появились замыкающие колонки `ns` и `asm` с сохранёнными пространством имён и сборкой строки `MissingType`. Журналы сборки и CI называют потерянный тип вместе с пространством имён (`Game.Pistol`, а не `Pistol`), чтобы одноимённые классы можно было различить.
- Поле `[SerializeReference]`, у которого на экземпляре префаба переопределены класс или собственные данные, имеет жирную подпись, а меню его заголовка предлагает **Revert** и **Apply to Prefab 'Name'**, как у собственных полей Unity. Изменение внутри вложенной ссылки отмечает только изменённое поле, а **Apply** не предлагается у варианта префаба, выбранного в **Project**. Синяя полоса override не рисуется; при выделении нескольких объектов нет ни подписи, ни пунктов.
- Поле `SerializableType` или `SerializableMonoScript` либо строка с `[TypeSelector]`, чей сохранённый тип больше не находится, показывает под полем уведомление **Missing type**. **Fix** открывает окно выбора, чтобы подобрать замену. Если класс только перенесли в другой namespace или сборку и подходящий тип с таким именем один, кнопка **→ ИмяТипа** заменяет сохранённое имя одним нажатием. Подпись показывает имя типа без сборки, `<Missing Game.Combat.Spear>`, а всплывающая подсказка — сохранённое имя целиком.
- `TypeField.AssemblyQualifiedName` возвращает сохранённое имя потерянного типа, для которого `value` равен `null`, так что кастомный редактор может записать имя обратно без изменений. `TypeField.ExcludeEditorOnlyTypes` стал публичным: непривязанное поле тоже может скрыть типы из editor-only сборок, как это делает привязанное поле на runtime-объекте.
- У `SerializableType`, `SerializableMonoScript` и их generic-вариантов появились `IsEmpty` (тип не сохранён) и `IsMissing` (имя сохранено, но больше не находится); `Type` в обоих случаях `null`. Unity заполняет сериализуемое поле пустой обёрткой, когда загружает ассет, сцену или префаб, поэтому одного `field == null` мало: проверяйте `field is null || field.IsEmpty`.
- Потерянные имена `SerializableType` и `SerializableMonoScript` находятся по всему проекту. **Project References → Scan Project** показывает их в группах **type name** с **Fix all**, **Smart Fix** и **Undo**; override экземпляров префабов и поля внутри managed-ссылок тоже переписываются. Проверка сборки и CI сообщает о них строками `MissingTypeName`: сохранённое имя — в столбце `className`, поле обёртки — в `fieldPath`. Обнаружение новых поломок сообщает об имени, которое перестало находиться. Строки с `[TypeSelector]` по-прежнему проверяются только в инспекторе.

### Изменено

- Минимальная версия Unity теперь 6000.0.53f1 вместо 6000.0.0f1. Пакет использует API UI Toolkit, которые появились в более поздних патчах 6000.0 (`IStyle.unityEditorTextRenderingMode`, `IStyle.unitySliceType`, `UxmlElement.libraryPath`), поэтому на ранних патчах он не компилировался.
- Пакет больше не содержит папку `Documentation` со страницами и картинками, поэтому они не импортируются в ваш проект; документация находится на сайте: https://vpdpersonal.github.io/Aspid.FastTools/. В каждом примере остался короткий текстовый README о том, как его открыть, со ссылкой на полное руководство на сайте.
- В пакет добавлен короткий `SETUP.md` с шагами установки и первыми шагами пакета из Asset Store, как офлайн-документация. `README.md` больше не указывает git URL, чтобы покупатель из Asset Store не добавил вторую копию пакета; установка по git URL осталась на сайте.
- У примеров новый вид. В каждом примере есть папка `Fonts` со шрифтами IBM Plex Serif, IBM Plex Mono и iA Writer Quattro S под лицензией SIL Open Font License 1.1 (тексты лицензий лежат рядом со шрифтами). В примерах со сценами (EnumValues, Types, SerializeReferences, ProfilerMarkers) есть ещё папка `Presentation` с цветными материалами и небольшим шейдером `Studio`. Ability Catalog из примера EditorTools берёт шрифты через `SampleFonts.uss`, а в его шапке появился выбор **Theme** (**Editor**, **Dark**, **Light**). Примеры выросли примерно с 0,2 до 3 МБ, в основном из-за копий шрифтов: пример импортируется отдельно, поэтому каждый несёт свои.
- Agent Skills для пакета переехали из плагина `aspid-fasttools` для Claude Code в [Aspid.Claude.Plugins](https://github.com/VPDPersonal/Aspid.Claude.Plugins) в этот репозиторий (`skills/`). Устанавливайте их в Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI или другой агент командой `npx skills add VPDPersonal/Aspid.FastTools`; плагин больше не публикуется.
- `GetScriptName()` переименован в `GetDisplayName()`, а `GetScriptNameWithIndex()` — в `GetDisplayNameWithIndex()`; замените старые вызовы новыми именами. Оба метода возвращают `string.Empty` для null и уничтоженных объектов. Поиск индекса компонента использует список из пула вместо временных массивов и LINQ.
- Переименованы расширения VisualElement; замените старые вызовы:
  - `SetIsDelayed` / `SetIsPassword` / `SetIsReadOnly` / `SetIsSelectable` → `SetDelayed` / `SetPassword` / `SetReadOnly` / `SetSelectable`;
  - `IsFocus` → `IsFocused`, `SetFocus` / `SetBlur` → `FocusSelf` / `BlurSelf`;
  - `EnableInClass` / `ToggleInClass` → `EnableClass` / `ToggleClass`;
  - `AddStyleSheetsFromResource` / `RemoveStyleSheetsFromResource` → `AddStyleSheetFromResources` / `RemoveStyleSheetFromResources`; `AddStyleSheets(sheet)` и `RemoveStyleSheets(sheet)` по-прежнему компилируются: имена во множественном числе теперь принимают несколько таблиц;
  - `SetImageFromResource`, `SetSpriteFromResource`, `SetVectorImageFromResource`, `SetBackgroundImageFromResource` → `…FromResources`;
  - `MarkDirtyLayout` → `MarkDirtyLayoutSelf`: `IMGUIContainer.MarkDirtyLayout()` перекрывал старое расширение, и вызов возвращал `void`; новое имя встраивается в цепочку.
  - `SetText` у `TextElement` (`Label`, `Button` и других) → `SetTextSelf`: начиная с Unity 6000.6 строковый аргумент связывается с собственным `TextElement.SetText(ReadOnlySpan<char>)` из Unity, который возвращает `void`, поэтому цепочки вида `label.SetText(x).SetTooltip(y)` не компилировались; новое имя встраивается в цепочку на любой версии Unity. `SetText` у `Foldout`, `HelpBox` и `Toggle` сохраняет имя.
- Вызов с голым `null` у `SetBackgroundImage` и, начиная с Unity 6000.6, у `SetTextSelf` больше не компилируется, потому что `null` подходит и к новым перегрузкам. Приведите его к типу, например `(string)null`, или передайте `StyleKeyword.None`, чтобы убрать фон.
- Классы расширений `BaseFieldExtensionsSetLabel<Type>` переименованы в `BaseField<Type>Extensions` (`BaseFieldExtensionsSetLabelInt` → `BaseFieldIntExtensions`), а `ProgressBarExtensions` — в `AbstractProgressBarExtensions`. Вызовы методов расширения не меняются; меняются только вызовы через имя класса.
- У `SetShowMixedValue` больше нет значения аргумента по умолчанию `true`; передавайте значение явно.
- `SetDirection`, `SetFill`, `SetInverted`, `SetPageSize` и `SetShowInputField` теперь возвращают собственный тип слайдера (`Slider`, `SliderInt`) вместо `BaseSlider<TValue>`, поэтому цепочка сохраняет члены слайдера. Они принимают `BaseSlider<float>` и `BaseSlider<int>`; открытые перегрузки для `BaseSlider<TValue>` удалены. Перегрузки для `BaseSlider<int>` находятся в новом классе `SliderIntExtensions`: вызовы методов расширения не меняются, но вызов через `SliderExtensions.` на `SliderInt` нужно заменить на `SliderIntExtensions.`.
- Конструкторы без параметров у `SerializableType` / `SerializableType<T>` больше не публичные: создавайте обёртку через `new SerializableType(type)` или `new SerializableType<T>(type)` (`null` даёт пустую). У `SerializableMonoScript` / `SerializableMonoScript<T>` нет публичных конструкторов: объявляйте их сериализуемыми полями и выбирайте скрипт в инспекторе.
- `SerializableType`, `SerializableMonoScript` и их generic-варианты теперь сравниваются по значению; `Equals` и `GetHashCode` раньше сравнивали ссылки. Обёртки с одним и тем же именем типа равны и дают одинаковый хеш-код, поэтому подходят в качестве ключей `Dictionary` и `HashSet`, а `List.Contains` и `IndexOf` находят равную обёртку. Оператор `==` по-прежнему сравнивает ссылки.
- `[TypeSelector]` на поле `[SerializeReference]` теперь предлагает только типы, совместимые со всеми типами атрибута, — по тому же правилу, что уже действовало для полей `string` и `SerializableType`; раньше достаточно было совпасть с одним из них. То же относится к `baseTypes` у `SerializeReferenceEditorGUI.CreateField`, `CreateList` и `DrawFieldLayout`. Список альтернатив вроде `typeof(Pistol), typeof(Rifle)` теперь оставляет селектор пустым и вызывает `AFT0009`: дайте разрешённым классам общий интерфейс или базовый класс и укажите его. `AFT0005` теперь проверяет все типы атрибута вместе.
- Анализатор `[TypeSelector]` больше не разбирает атрибуты полей без `[TypeSelector]` и пропускает сборки, которые не ссылаются на пакет; раньше это замедляло каждую компиляцию большого проекта.
- IMGUI-инспектор больше не проверяет список `[SerializeReference]` на дубликаты целиком для каждого элемента на каждом GUI-событии: проверка идёт один раз на список за такт редактора или при изменении размера списка. Поле с общей ссылкой больше не создаёт `SerializedObject` на каждой перерисовке.
- `GetFieldInfo()` и `GetDeclaringInstance()` кэшируют поиск поля, а проверка, есть ли у вложенного поля `[SerializeReference]` собственный drawer, кэшируется для каждого поля. IMGUI-инспектор больше не создаёт массивы и экземпляры атрибутов для каждой вложенной ссылки на каждом событии, а строк создаёт меньше, поэтому на большом дереве при движении мыши выделяется меньше памяти.
- **Fix all**, **Smart Fix**, **Migrate all**, `<None>` и **Undo** в сводке Project References больше не перечитывают файл на каждую сломанную ссылку в нём, а записывают его один раз. Проверка, открыт ли файл или есть ли в нём несохранённые изменения, тоже идёт один раз на файл. Поэтому файл с большим числом сломанных ссылок исправляется намного быстрее.
- Пустое поле `[SerializeReference]` больше не разбирает файл ассета на каждой перерисовке, чтобы проверить потерянный тип: неизменённый файл читается один раз, поэтому пустые поля в большой сцене или префабе больше не замедляют инспектор.
- В инспекторе runtime-объекта селектор типов больше не предлагает типы из editor-only сборок (`UnityEditor`, asmdef только для Editor и папки `Editor`): плеер не может их найти, и в билде значение молча становилось `null` или потерянной ссылкой. Поля окон редактора и других editor-only объектов по-прежнему предлагают любые типы.
- **Paste**, **Paste Template**, *Link to Existing*, перетаскивание скрипта и **Smart Fix** в инспекторе runtime-объекта следуют тому же правилу: они больше не назначают тип из editor-only сборки или generic-тип с таким аргументом. Селектор типов в Asset References тоже больше не предлагает такие типы для runtime-объекта. **Create New Script…** не меняет поле и пишет предупреждение, если новый скрипт сохранён в папке `Editor`.
- Селектор типов без ограничений (`SerializableType` без `T`, `[TypeSelector]` на строке, `TypeField`) переиспользует список типов между открытиями, а не собирает его заново из всех загруженных типов.
- Селектор типов сначала проверяет базовый тип поля, когда перебирает загруженные типы, поэтому селектор с узким базовым типом, например **+** списка `[SerializeReference]` конкретного интерфейса, открывается в большом проекте в несколько раз быстрее. IMGUI-поле типа разрешает сохранённое имя типа один раз, а не на каждой перерисовке; потерянный тип делал это медленным.
- `TypeField(string label, Type defaultValue = null)` разделён на `TypeField(string label)` и `TypeField(string label, Type defaultValue)`, `InspectorTypeField` — так же. `new TypeField(null)` раньше выбирал конструктор со свойством и бросал `NullReferenceException`; теперь вызов не компилируется — укажите имя аргумента: `new TypeField(label: null)`. Привязанные конструкторы бросают `ArgumentNullException` для свойства `null` и `ArgumentException` для свойства не строкового типа. С `binding-path` в UXML поле пишет предупреждение, что привязать его можно только из C#.
- Чтение `Type` у `SerializableType` и `SerializableMonoScript` открывает маркер профайлера только для поиска типа, а не для чтения из кэша, поэтому чтение у многих объектов в каждом кадре больше не забивает профайлер сэмплами.
- `SerializeReferenceIMGUIList.Draw` теперь бросает `ArgumentNullException` для свойства `null` и `ArgumentException` для свойства, которое не является списком managed references, как `SerializeReferenceEditorGUI.CreateList`; раньше он ничего не рисовал. Метка `null` теперь показывает отображаемое имя свойства; чтобы скрыть её, передайте `GUIContent.none`.
- Сгенерированный код `this.Marker()` теперь объявляет поля маркеров только под `ENABLE_PROFILER`, как и тело `Marker()`, которое их читает: сборки без профайлера больше не создают все маркеры в статическом конструкторе.
- `ProfilerMarkerExtensionsForGenerator.Marker(this object)` стал `Marker<T>(this T, [CallerLineNumber] int line = -1)`: вызов в структуре, которую генератор не может обработать, больше не упаковывается, и Burst-джоба компилируется. Параметры у него те же, что у сгенерированной перегрузки, поэтому маркеры получает и тип без пространства имён, как в шаблоне скрипта Unity. Вызов `this.Marker()` внутри дерева выражений больше не компилируется (CS0854), а группе методов теперь нужен `Func<int, AutoScope>`.
- Generic-класс называет вложенные аргументы типа так, как их пишет C# (`Foo<List<Int32>>.Run (line)`, `Foo<Outer<Int32>.Inner>.Run (line)` вместо ``Foo<List`1>``, `Foo<Inner>`). Generic-структура получает один маркер на точку вызова для всех закрытых типов с именем `Job<T>.Execute (line)`, потому что Burst не может выполнить метку для каждого типа.
- Сгенерированный `Marker()` выбирает маркер по строке через `switch`, поэтому его стоимость больше не растёт с числом точек вызова в типе.
- Сгенерированный `Marker()` принимает структуру по `in`, поэтому `this.Marker()` в структуре, например в большой джобе, больше не копирует весь экземпляр при каждом вызове. Копия делалась в Mono (редактор, Mono-плееры) и в IL2CPP, когда вызов и перегрузка попадали в разные C++-файлы.
- Скриптовый символ, который вырезает собственные маркеры профилировщика пакета, теперь называется `ASPID_FASTTOOLS_UNITY_PROFILER_DISABLED`, как и остальные символы `ASPID_FASTTOOLS_*`. Старый `ASPID_FAST_TOOLS_UNITY_PROFILER_DISABLED` больше не работает: переименуйте его в **Scripting Define Symbols**.
- `Aspid.FastTools.VisualElements.Math` больше не компилируется пустой сборкой в проектах без `com.unity.mathematics`.
- Анимированный фон из точек в окне FastTools и на странице настроек рисует все точки одним мешем, а не тесселирует отдельный путь на каждую точку в каждом кадре, и замирает, пока Unity в фоне, поэтому открытое окно без действий больше не нагружает редактор.
- Фон из точек перерисовывается 20 раз в секунду вместо 30. Новый переключатель **Animated background** (окно FastTools → Settings → Appearance и Preferences → Aspid.FastTools → Appearance) останавливает анимацию и таймер перерисовки.
- Градиент при наведении на кнопку в окнах FastTools запускает таймер только на время затухания, а все градиентные кнопки используют одну общую текстуру градиента вместо собственной.
- Окно FastTools (Welcome, Asset References, Project References и Settings) и его страницы в Project Settings и Preferences учитывают светлую тему редактора: фон, карточки, текст, статусные цвета и окно выбора типа внутри него берут светлую палитру `Aspid-FastTools-Default-Light.uss`; раньше они оставались тёмными в обеих темах. Theme override по-прежнему накладывается поверх любой из палитр.
- `[TypeSelector]` на поле-массиве или `List<T>` теперь относится ко всей коллекции (`applyToCollection`): его drawer рисует список и выбор типа для каждого элемента. `PropertyField` и `EditorGUILayout.PropertyField` для такого списка теперь получают **+** с выбором типа в UI Toolkit и IMGUI, а `PropertyField` для отдельного элемента больше не показывает выбор типа. `SerializeReferenceIMGUIList.Draw` и `SerializeReferenceEditorGUI.CreateList` добавляют к `baseTypes` ограничения `[TypeSelector]` с поля списка. Списки managed references, которые рисует пакет, теперь учитывают `[NonReorderable]`.
- Параметр `value` у `AddClass`, `RemoveClass`, `ToggleClass`, `AddStyleSheet`, `RemoveStyleSheet` и их вариантов `…If` переименован в `className` и `styleSheet`; вызов с именованным аргументом `value:` нужно обновить.
- Методы таблиц стилей, например `AddStyleSheet` и `RemoveStyleSheet`, пропускают `null` вместо `ArgumentNullException`.
- `RemoveChild` и `RemoveChildren` пропускают `null` и элементы, которые не являются дочерними, вместо исключения, поэтому `RemoveChildren` больше не останавливается на полпути.
- Расширения для дочерних элементов, классов и таблиц стилей размечены для nullable reference types: проект с включённой проверкой видит, какие аргументы могут быть `null`.

### Удалено

- Из расширений `SerializedProperty` удалён `SetExposedReferenceAndApply()`; вызывайте `SetExposedReference()`. Без контекста `IExposedPropertyTable` сеттер `exposedReferenceValue` в Unity сам применяет запись и записывает Undo, поэтому дополнительное применение ничего не делало, а вариант без Undo поверх него построить нельзя.
- Удалено editor-only свойство `SerializableMonoScript.Script`, которое возвращало ассет `MonoScript`; публичного доступа к ассету больше нет. Тип по-прежнему доступен через `Type` или неявное преобразование в `Type`.
- Удалены `AddMakeItem` / `RemoveMakeItem` у `ListView` и `TreeView`, а также `AddMakeHeader` / `AddMakeFooter` / `AddMakeNoneElement` у `BaseListView` вместе с парами `Remove*`; у списка одна фабрика, поэтому вызывайте `SetMakeItem`, `SetMakeHeader`, `SetMakeFooter` или `SetMakeNoneElement`.
- Удалены перегрузки `Span<VisualElement>` у `AddChildren`, `InsertChildren` и их вариантов `…If`. Аргумент `Span` преобразуется в перегрузку `ReadOnlySpan`, поэтому существующие вызовы компилируются без изменений.
- Runtime-методы `Aspid.FastTools.StringExtensions.ToKebabCase` и `Aspid.FastTools.TypeExtensions.GetMembersInfosIncludingBaseClasses` убраны из публичного API без замены.

### Исправлено

- `InsertChildren` и `InsertChildrenIf` пропускают `null` без сдвига индекса: `InsertChildren(0, a, null, b)` ставит `b` сразу после `a`; раньше оставался пропуск, а в конце родителя вызов бросал `ArgumentOutOfRangeException`.
- `SetValue`, `SetValueAndApply` и `SetValueAndApplyWithoutUndo` снова компилируются с аргументом `byte`, `sbyte`, `short`, `ushort` или `char` на Unity 6000.2 и новее: перегрузка для `EntityId` делала вызов неоднозначным (CS0121). Теперь у каждого из этих типов своя перегрузка, которая вызывает `SetInt`.
- XML-документация расширений UI Toolkit теперь совпадает с поведением. `SetValue(value, notify: true)` шлёт событие изменения, только если элемент в панели, а значение отличается. `SetPadding(8, 4)`, как `SetMargin`, `SetBorderWidth`, `SetBorderColor`, `SetDistance`, задаёт верхнюю и правую стороны. Слайдеру нужен диапазон до `SetValue`. Встроенную лямбду, переданную в `AddValueChanged`, нельзя снять через `RemoveValueChanged`. У `ListView` и `TreeView` `AddChild` бросает исключение, а `InsertChild`, `RemoveChildAt`, `ClearChildren` ничего не делают. Каждый метод, который есть только в новых версиях Unity, содержит строку `Available in Unity 6000.x and newer`.
- Значок `SHARED` в Asset References теперь вмещает свой текст; раньше он сжимался до ширины цветной точки, текст вылезал за его край, а точка закрывала букву «H».
- Asset References показывает незаполненные обязательные поля (карточки **Required type is not set** и значки REQUIRED) ассета из папки **Excluded scan folders**, как уже показывал его потерянные типы; в Project References и проверки build / CI такой ассет по-прежнему не попадает.
- Asset References больше не вешает редактор на ассете, где объекты `[SerializeReference]` ссылаются друг на друга: окно рисовало карточку на каждый путь по графу, а число путей растёт экспоненциально. Теперь объект показывает свои дочерние ссылки один раз, под первой карточкой, которая не стоит под потерянным типом; другое поле, которое на него указывает, получает свою карточку и свой путь поля, с пометкой **children on another card** в подвале. Окно рисует не больше 1000 карточек ссылок и сообщает, сколько пропустило; Project References исправляет потерянные типы без этого предела. Ассет со списком из тысяч объектов к тому же открывается быстрее.
- `GetDisplayName()` и `GetDisplayNameWithIndex()` больше не добавляют « (Script)», когда `[AddComponentMenu]` унаследован от базового класса или его путь пуст либо заканчивается на `/`; такие типы получают «очеловеченное» имя типа. Заголовок теперь берётся из атрибута, объявленного на самом типе, а тип с `[Obsolete]` больше не получает « (Deprecated)».
- Ссылка на член `[TypeSelector(nameof(...))]` у поля внутри `[Serializable]`-класса или элемента списка теперь разрешается на экземпляре, который объявляет поле, — так её уже проверяют анализаторы `AFT0006`–`AFT0008`. Раньше член искался на инспектируемом компоненте или ассете, и инспектор показывал предупреждение. То же относится к селектору окна Asset References.
- Если getter члена, на который ссылается `[TypeSelector(nameof(...))]`, бросает исключение, поле больше не ломается ошибками в консоли: оно рисуется без этого ограничения, а под ним появляется предупреждение с текстом исключения.
- `AFT0007` больше не ломает компиляцию на члене типа `Type?` при `#nullable enable` и теперь сообщает о свойстве без getter, которое инспектор не может прочитать. `AFT0004` теперь сообщает и о поле `UnityEngine.Object?`.
- `AFT0005` больше не предупреждает о generic-типе поля или базовом типе (`IState<Enemy>`, `Base<int>`, `typeof(IFoo<int>)`), у которого есть закрытая или открытая generic-реализация, и о реализации через `out`/`in`-вариантность — она больше не вызывает и `AFT0003`. Ни одно из них не срабатывает на поле типа generic-параметра (`T` в `Slot<T>`). Несвязанный `typeof(Base<>)` больше не вызывает `AFT0003` и `AFT0005`, если поле может заполнить открытая generic-реализация вроде `Impl<T> : Base<T>`.
- `[field: TypeSelector]` и `[field: SerializeReference, TypeSelector]` на автосвойстве теперь проверяются правилами `AFT0001`–`AFT0009`, а `AFT0003` теперь проверяет и поля `SerializableType<T>` и `SerializableMonoScript<T>`.
- `AFT0008` теперь сообщает также об имени типа в `[TypeSelector]` без сборки, например `"Game.IWeapon"`, с подсказкой, какую сборку дописать: инспектор ищет такое имя только в mscorlib, поэтому пикер терял ограничение без предупреждения при компиляции.
- Тип поля или аргумент `typeof(...)`, который компилятор не может найти (пропала ссылка asmdef, класс ещё не создан) или чей базовый класс либо интерфейс он не может найти, больше не вызывает `AFT0001`, `AFT0003`, `AFT0005` или `AFT0009` вдобавок к ошибке компилятора.
- `AFT0005` теперь предупреждает, если класс из `typeof(...)` не подходит под тип поля и ни один его наследник тоже не подходит, например `[TypeSelector(typeof(Sword))]` на поле `IShield`; раньше селектор был пуст без предупреждения. Сообщение `AFT0005` теперь называет и тип поля, если он сужает выбор.
- `AFT0001` больше не ломает компиляцию на поле `[Serializable]`-наследника `SerializableType` с конструктором без параметров, которое инспектор рисует, а `AFT0007` принимает член любого типа `ISerializableType`, который инспектор читает.
- `AFT0003`–`AFT0006` называют типы с пространством имён и аргументами типа, поэтому два закрытых типа одного generic больше не выглядят как `'Slot'` и `'Slot'`.
- **Fix** и **Smart Fix** отсутствующего типа в сохранённом ассете в инспекторе UI Toolkit больше не выводят исключение; поля ссылок в других инспекторах обновляются сразу после ремонта.
- Потерянный тип `[SerializeReference]`, сохранённый без namespace, больше не сопоставляется с посторонним классом, у которого `[MovedFrom]` называет то же старое имя класса: gate и Project References не показывают его как ожидающую миграцию, **Migrate all** не переписывает его на этот класс, а Smart Fix не ставит этот класс первым.
- В Edit Mode уведомление *Shared reference*, его номер и пункт *Make Unique Reference* теперь обновляются сразу после правки из IMGUI-инспектора, через *Link to Existing* или в окне графа ссылок; раньше они показывали состояние до правки, пока не сменится выделение.
- Поле `[SerializeReference]` теперь всегда раскрывается и показывает новое значение после выбора типа, перетаскивания скрипта, **Paste**, **Paste Template** или *Link to Existing*. Раньше оно могло остаться свёрнутым: в IMGUI-инспекторе после любого из этих действий, в инспекторе UI Toolkit — после перетаскивания, шаблона или ссылки.
- Если у нескольких выделенных объектов поле `[SerializeReference]` хранит один и тот же тип, поле показывает этот тип с его полями для общей правки; раньше оно показывало «—» с подсказкой *Different types selected*, если объекты не были точными копиями.
- Смена типа теперь сохраняет те же экземпляры в полях `[SerializeReference]` внутри структур, сериализуемых классов, массивов и списков, а также в приватных полях `[SerializeReference]` без `[SerializeField]` (включая автосвойства с `[field: SerializeReference]`), как уже сохраняла другие вложенные ссылки; раньше туда попадали копии, поэтому поля, которые указывали на эти экземпляры, теряли связь. **Make unique** и исправление продублированного элемента списка теперь копируют такие ссылки вместе с остальными данными ссылки: два поля с общим экземпляром получают общую копию.
- Вложенное поле `[SerializeReference]` теперь сохраняет пользовательский drawer, зарегистрированный для его объявленного типа через открытый generic-тип (`typeof(Effect<>)`), базовый класс или интерфейс, даже без `useForChildren`, а также drawer базового класса атрибута; раньше пакет рисовал поверх них свой заголовок и выбор типа. Во вложенном списке такой drawer рисует каждый элемент и в IMGUI, и в UI Toolkit, а **+** сохраняет выбор типа. Drawer только хранимого типа выбор типа не заменяет.
- Вложенное поле `[SerializeReference]` без `[TypeSelector]` сохраняет `[Header]`, `[Space]` и `[Tooltip]` в IMGUI-инспекторе, как в UI Toolkit; IMGUI рисовал его без заголовка, отступа и подсказки.
- Несколько атрибутов `[Header]` или `[Space]` на одном вложенном поле `[SerializeReference]` больше не заставляют UI Toolkit Inspector бросать `AmbiguousMatchException` и не оставляют остальные поля объекта нерисованными; они рисуются по `order`.
- Вложенный список `[SerializeReference]` с пользовательским атрибутом для каждого элемента (`PropertyAttribute` с drawer-ом и выключенным `applyToCollection`) сохраняет **+** с выбором типа; раньше он превращался в обычный список Unity, где **+** добавляет элемент без выбора типа. Drawer атрибута по-прежнему рисует каждый элемент.
- Пользовательский drawer с `[SupportedOnRenderPipeline]` для другого render pipeline, а в Built-in pipeline любой drawer с такой пометкой, больше не отнимает выбор типа у вложенного поля `[SerializeReference]`. Unity такой drawer не использует, поэтому поле оставалось ни с чем; теперь пакет тоже его игнорирует.
- Сброс пользовательских настроек больше не перечисляет в подсказке и диалоге подтверждения удалённую опцию «Dropdown without [TypeSelector]».
- Клавиатурный фокус на вкладке Settings хорошо виден: у выбранной строки, кнопки сброса, заголовка **Excluded scan folders** и папки в списке появляется заметная рамка. Одна заливка выглядела как наведение.

- `Persistent()` больше не оставляет неосвобождённым созданный `SerializedObject`, если путь свойства больше не существует на целевых объектах: он освобождается перед возвратом `null`.
- `AddChildren`, `InsertChildren` и их варианты `…If` с `IEnumerable` больше не бросают `InvalidOperationException` («Collection was modified»), когда получают `Children()` другого элемента: `target.AddChildren(source.Children())` переносит всех детей.
- `TryGetByEnum` возвращает `false` для числа из USS, которого нет среди значений enum (`--preview-theme: 7;`) и для списка через запятую у enum без `[Flags]`, и элемент сохраняет значение по умолчанию вместо несуществующего. `[Flags]`-enum принимает только имена.
- Пример Types: селектор `Enemy Type` больше не предлагает абстрактный `Enemy`, из-за которого появлялись пустые капсулы и ошибка на каждого врага; шаг README с переименованием теперь использует Rename-рефакторинг IDE, и `ArmoredGrunt` продолжает компилироваться.
- Пример Types: `Brute` больше не уходит наполовину под платформу; его высота теперь зависит от масштаба.
- Пример SerializeReferences: при импорте больше нет предупреждения CS0414, а удаление Training Dummy в Play Mode больше не бросает `MissingReferenceException` на каждом выстреле.
- Пример EditorTools: окно Ability Catalog отслеживает ассеты, созданные или удалённые в окне Project, а **Create** выделяет новый ассет и при активном поиске.
- Пример EditorTools: окно Ability Catalog сохраняет текст поиска в раскладке окон, поэтому он переживает перезапуск редактора.
- Примеры EnumValues и ProfilerMarkers больше не ломают компиляцию проекта без встроенного модуля Physics: там их скрипты пропускаются, а в описаниях примеров сказано, что модуль нужен.
- Пример EnumValues: Walker больше не ставит `[InspectorName]` на поля, где Unity его игнорирует (атрибут читается только у значений enum); подписи в инспекторе — **Step Interval** и **Footprint Lifetime**, а **Log Tables** выводит ту же подпись.
- Примеры Types и SerializeReferences: в описаниях и README сказано, что коллайдерам их сцен нужен встроенный модуль Physics.
- Внутренние элементы редактора пакета (`AspidBox`, `AspidLabel` и ещё десять) больше не показываются в UI Builder Library вашего проекта: они сделаны для окон FastTools и в вашем UXML выглядят без оформления.
- Иконка вкладки окна FastTools — текстура 64×64 с mipmaps (7 КБ) вместо 1022×1011 без них (583 КБ): пакет стал меньше, а края иконки остаются гладкими при 16 pt.
- `Persistent()` сохраняет `context` исходного `SerializedObject`, поэтому `ExposedReference`, прочитанный или записанный через копию, разрешается в той же таблице (например, `PlayableDirector`), а не в значении по умолчанию в ассете.
- *Link to Existing* в контекстном меню `[SerializeReference]` теперь предлагает только экземпляры, которые принимает выбор типа поля с учётом базовых типов `[TypeSelector]`, в том числе заданных ссылкой на член; раньше он предлагал любой экземпляр, совместимый с объявленным типом поля.
- `SerializeReferenceEditorGUI.CreateField` и `DrawFieldLayout` теперь добавляют к `baseTypes` ограничения `[TypeSelector]` поля, как это уже делал `CreateList`. Раньше окно выбора предлагало все типы, подходящие объявленному типу поля, а `PropertyField` предлагает только выбранные. `CreateField` читает ограничение один раз, при создании поля.
- *Find Usages* в контекстном меню `[SerializeReference]` теперь находит использования именно того типа, что лежит в поле (с учётом пространства имён и сборки); раньше в результаты попадало любое хранимое имя класса, содержащее его имя, например `PistolMk2` или `Pistol` из другого пространства имён. Запрос `sr:`, набранный вручную, по-прежнему ищет по подстроке имени класса.
- *Find Usages of …* и *Link to Existing* в контекстном меню `[SerializeReference]` называют generic-тип так же, как выбор типа: `Modifier<Single>` или имя из `[TypeSelectorDisplay]`; раньше там было ``Modifier`1``. Символ `/` в отображаемом имени больше не открывает подменю.
- В стандартном UI Toolkit Inspector **+** пустого списка `[TypeSelector]` `[SerializeReference]` теперь открывает выбор типа; раньше он добавлял элемент `<None>`, а выбор типа появлялся, только когда в списке уже был элемент.
- Уведомление о поломке ссылок и настройка детектора поломок указывают на Project References, а не на старое имя вкладки — Repair.

## [1.0.0-rc.8] — 2026-09-06

Первый релиз. Unity **6000.0**, сборки `Aspid.FastTools` / `Aspid.FastTools.Editor`, предсобранные Roslyn-DLL `Aspid.FastTools.Generators` / `Aspid.FastTools.Analyzers`. Все инспекторные возможности работают и в IMGUI, и в UI Toolkit.

### Добавлено

#### Serializable Type System

- `SerializableType` / `SerializableType<T>` — `[Serializable]`-обёртка над `System.Type`, ленивое разрешение, неявное приведение к `Type`, конструктор с `Type`, `AssemblyQualifiedName`.
- `SerializableMonoScript` / `SerializableMonoScript<T>` — то же, но через ассет скрипта, поэтому переименование и перенос класса ничего не ломают; плеер сериализует одно имя.
- `SerializableTypeBase` и `ISerializableType` для полиморфной работы с любой обёрткой.
- `[TypeSelector]` — иерархический пикер типов на полях `string`, `SerializableType` / `SerializableMonoScript` и `[SerializeReference]`, а также на массивах и списках из них. Ограничения базовыми типами, `Allow` (`TypeAllow`), `Required`, ссылки на члены в строковых аргументах (`Type`, `string`, `SerializableType`, массивы из них, разрешаются вживую).
- `[TypeSelectorDisplay]` — `Name`, `Group`, `Tooltip`, `Icon`, `Hidden` для строки типа в пикере.
- `ComponentTypeSelector` — заменяет соседний `Component` на месте через дропдаун типов.
- `TypeSelectorWindow` с публичным API `Show(...)`: дерево пространств имён, поиск, навигация с клавиатуры, Favorites и Recent, `TypeSelectorFilter` (`Predicate`, `AdditionalTypes`, `HideNoneOption`).
- UI Toolkit-элементы `TypeField` / `InspectorTypeField`, на которых построены drawer'ы.

#### SerializeReference Selector

- Дропдаун типов на полях `[SerializeReference]`, включая вложенные ссылки (до 8 уровней); кастомные drawer'ы и `[Header]` / `[Space]` / `[Tooltip]` учитываются.
- Открытые generic-реализации: аргументы выводятся из аргументов типа поля и его интерфейсов, иначе собираются на второй странице пикера.
- Перенос данных при смене типа, Copy / Paste, мультиредактирование, развязывание дубликатов.
- Уведомления об общих ссылках с **Make unique**, цветными группами и переходом к участникам.
- Назначение перетаскиванием `MonoScript`, именованные шаблоны, **Link to Existing**, `+` списка через пикер, **Create New Script…**, **Find Usages**.

#### Починка потерянных ссылок

- Встроенный **Fix** на потерянном типе с сохранением данных; работает для сохранённых ассетов, Prefab Mode и объектов сцены.
- **Smart Fix** ранжирует вероятную замену (`[MovedFrom]`, то же имя в другом месте, регистр, совпадение формы полей).
- Переименования `[MovedFrom]` показываются как ожидающие миграции с **Migrate all** в один клик и не считаются нарушениями.
- Уведомление о поломке после переименования / удаления скрипта или реимпорта; защита удаления скриптов, используемых как managed reference; предпросмотр YAML-diff перед каждой массовой перезаписью.

#### Рабочее окно (`Tools → Aspid 🐍 → FastTools`)

- **Welcome** — примеры с отметками установки; открывается автоматически один раз на версию пакета.
- **Asset References** — весь граф `[SerializeReference]` ассета из YAML с предупреждающей полосой на отсутствующих типах и бейджами `SHARED`, встроенным Fix, Clear для осиротевших записей, Open Source Prefab.
- **Project References** — `Scan Project` по `Assets/`, **Fix all** на тип с Undo, Smart Fix, Migrate all, Required violations.
- **Settings** — все настройки пакета с полосками области (общая / пользовательская) и сбросом по областям.
- Навигация с клавиатуры, легенды, контекстные меню строк на каждой вкладке.
- Проектный индекс использований, провайдер Quick Search `sr:`.
- Build / CI gate: `IPreprocessBuildWithReport` плюс headless `SerializeReferenceCiGate.RunCheck` с `-srGateReport`, `-srGateRequired`, `-srGateWarnOnly`, `-srGateFail`; строгость `Off` / `Warn` / `Fail` и исключённые папки в коммитимом `ProjectSettings/SerializeReferenceSharedSettings.asset`.

#### Настройки

- **Project Settings → Aspid.FastTools → SerializeReference** — авторазвязывание, обнаружение поломок, строгость gate, исключённые папки.
- **Preferences → Aspid.FastTools** — зеркало вкладки Settings: References, Type Selector (Favorites, ёмкость Recent), Welcome, тема.

#### Диагностики анализатора

- `AFT0001` (ошибка) — `[TypeSelector]` на неподдерживаемом поле.
- `AFT0002` (предупреждение) — `Allow` на managed reference игнорируется.
- `AFT0003` (предупреждение) — базовый тип не имеет общих конкретных типов с полем.
- `AFT0004` (ошибка) — `[SerializeReference]` на типе `UnityEngine.Object`.
- `AFT0005` (предупреждение) — ни один конкретный сериализуемый тип не удовлетворяет ограничениям.
- `AFT0006` (ошибка) — строковый аргумент не является ни членом, ни именем типа.
- `AFT0007` (ошибка) — указанный член не может задавать базовые типы.
- `AFT0008` (предупреждение) — строка-не-идентификатор не является корректным именем типа.

#### ProfilerMarkers

- `this.Marker()` — `ProfilerMarker`, уникальный для места вызова.
- `ProfilerMarkersGenerator` — создаёт по полю маркера на место вызова; поддерживает лямбды, локальные функции, `.WithName(...)` и имена `$"..."`; вырезается без `ENABLE_PROFILER`.

#### EnumValues

- `EnumValues<TValue>` — сериализуемый словарь с ключом-enum, значением по умолчанию и поддержкой `[Flags]`.
- `EnumValues<TEnum, TValue>` — типизированный вариант, поиск без боксинга, структурный перечислитель.
- Drawer'ы с редактированием на месте и **Populate Missing Enum Members**.

#### Fluent-расширения VisualElement

- Fluent API на `VisualElement`: раскладка, стиль, границы, цвета, переходы, колбэки, USS, управление детьми с вариантами `*If`, пресеты стилей.
- Помощники для `Button`, `BaseField<T>` (`SetLabel` для 29 типов), `Focusable`, `Foldout`, `HelpBox`, `Image`, `IMGUIContainer`, `IMixedValueSupport`, `INotifyValueChanged`, `IStyle`, `ICustomStyle`, list view, `Manipulators`, `ProgressBar`, `Slider`, `TextElement`.
- Редактор: `BindTo` / `UnbindFrom`, `BindPropertyTo`, `SetBindingPath`, `SetLabel` для `PropertyField`, `AddOpenScriptCommand`, `GetOwnerWindow`.
- `Aspid.FastTools.VisualElements.Math` — `SetValue` / `ValueChanged` для типов `Unity.Mathematics`, компилируется только с `com.unity.mathematics`.

#### Расширения SerializedProperty

- Типизированные сеттеры `Set*` / `Set*AndApply`, `Update`, `ApplyModifiedProperties`, `Persistent`, помощники путей, `GetPropertyType` / `GetFieldInfo` / `GetDeclaringInstance`.
